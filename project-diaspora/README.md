# Project Diaspora

미지의 행성을 탐사하며 위협 요소를 회피하고 전리품을 수집하는 PC 3D 공포 탐사 생존 게임입니다.

## 개발 환경

- Engine: Unity
- Language: C#
- 인원: 11인 팀 프로젝트

## 담당 기능

- 몬스터 AI (Spirit / Coilhead)
- PDA 시스템
- 인벤토리 / 스캔 시스템

## 기능 상세

### 몬스터 AI — Spirit / Coilhead

NavMesh 기반 배회, Camera Viewport 기반 시선 판별, Raycast 기반 장애물 가림 판별을 결합해 공포 장르에 맞는 상태 전환 로직을 구현했습니다.
단순 추격이 아니라 보일 때와 안 보일 때의 위협 차이를 플레이로 전달하는 데 집중했습니다.

**Spirit**
플레이어의 시선 유지 시간과 거리 조건에 따라 배회(Wander), 도망(Flee), 추격(Chase) 상태로 전환되는 시선 반응형 몬스터 AI입니다.

- Viewport로 몬스터가 화면 안에 있는지 1차 판별하고, Raycast로 장애물에 가려졌는지 2차 검증했습니다.
- lookTimer와 forcedChase 상태를 기준으로 배회, 도망, 추격 중 하나의 행동만 선택되도록 설계했습니다.
- 플레이어가 짧게 바라보면 도망 상태로, 일정 시간 이상 바라보면 강제 추격으로 전환해 예측하기 어려운 긴장감을 구현했습니다.

**Coilhead**
플레이어가 보고 있을 때는 멈추고, 시야에서 벗어나면 추적하는 Line of Sight 기반 몬스터 AI입니다.

- WorldToViewportPoint로 몬스터가 카메라 화면 안에 들어왔는지 확인하고, Raycast를 추가로 사용해 벽이나 오브젝트에 가려진 상태인지 검증했습니다.
- 화면 안에 있고 실제로 보이는 경우 NavMeshAgent를 정지시키고, 보이지 않는 경우 플레이어 위치를 목적지로 설정했습니다.

### PDA 시스템

유물, 기록, 퀘스트 관련 정보를 한 곳에서 확인할 수 있도록 구성한 탐사 기록 UI입니다.

- ArtifactData를 ScriptableObject로 분리하고, 각 유물은 고유 ID로 관리했습니다.
- 등록 여부는 HashSet으로 관리해 중복 등록을 방지했습니다.
- PDA 패널이 꺼져 있는 동안 획득한 유물도 OnEnable 시점에 UI에 반영되도록 구성했습니다.

---

### 인벤토리 / 스캔 시스템

아이템 획득, 보관, 스캔을 연결해 탐사 중 필요한 상호작용 흐름을 구성한 시스템입니다.

- 아이템 획득 시 메인 인벤토리 4칸을 우선으로 확인하고, 메인 슬롯이 가득 찬 경우 서브 인벤토리 8칸으로 확장되도록 처리했습니다.
- 스캔 기능은 확장되는 SphereCollider 파동이 가장 먼저 닿은 ScanableItem만 처리하고, Line of Sight 검사를 통해 벽 뒤 오브젝트는 제외했습니다.

## 트러블슈팅

### 1. Coilhead 시선 판별 정확도 문제

**PROBLEM**
초기에는 Camera Viewport 판별만으로 '몬스터를 보는 중' 여부를 결정했습니다.
이 방식은 장애물 뒤에 몬스터가 숨어 있어도 화면 영역 안에 포함되면 정지 상태를 유지해, 벽이나 선반 뒤에서 실제로 위협해야 할 순간에 몬스터가 멈춰버리는 오판정이 발생했습니다.
공포 게임의 핵심 장치인 '시야 밖에서 접근하는 위협'이 사실상 사라진 상황이 됐습니다.

**APPROACH**
Viewport 판별을 1차 조건으로 유지하되, 통과한 경우에만 카메라에서 몬스터 방향으로 Raycast를 추가 발사해 실제 가시성을 검증했습니다.
Raycast가 도달한 오브젝트가 몬스터 자신이 아닌 경우, 즉 중간에 장애물이 있을 경우 '보이지 않음'으로 처리해 두 조건을 독립적으로 분리했습니다.

**RESULT**
장애물 뒤 몬스터의 잘못된 정지가 사라졌습니다.
플레이어가 벽 너머로 이동하는 순간 즉시 추격을 재개하는 의도된 위협 사이클이 안정적으로 유지됐습니다.

### 2. Spirit AI 상태 플래그 초기화 누락으로 인한 행동 오작동

**PROBLEM**
초기 구현에서는 shouldFlee, shouldChase 상태 플래그가 이전 프레임의 값을 유지한 채 다음 조건 분기로 넘어가면서, 도망과 추격 목적지가 같은 프레임에 중복 설정되는 문제가 있었습니다.
그 결과 NavMeshAgent.SetDestination이 서로 다른 방향으로 반복 호출되어 몬스터가 제자리에서 흔들리거나 의도하지 않은 경로를 계산하는 현상이 발생했습니다.

**APPROACH**
Update 루프에서 shouldChase와 shouldFlee를 지역 변수로 선언해 매 프레임 false 상태에서 다시 평가되도록 수정했습니다.
이후 forcedChase, Flee, Chase 조건을 순서대로 검사해 한 프레임 안에서 하나의 행동 상태만 선택되도록 정리했습니다.

**RESULT**
이전 프레임의 상태 플래그가 남아 Flee와 Chase가 동시에 처리되는 문제가 사라졌습니다.
NavMeshAgent.SetDestination 호출도 하나의 최종 상태에 대해서만 실행되어, 몬스터가 제자리에서 흔들리거나 경로를 반복 재계산하는 현상을 없앴습니다.
