# Help Mini Game

짧은 시간 안에 여러 릴레이 미니게임을 플레이해 점수를 쌓는 모바일 2D 캐주얼 게임입니다.

## 개발 환경

- Engine: Unity
- Language: C#
- 인원: 6인 프로젝트

## 담당 기능

- 실 통과 게임
- 운석 피하기 게임

## 기능 상세

### 실 통과 게임

랜덤 시드 기반 PerlinNoise로 흔들리는 바늘을 피해 목표 지점을 통과하는 2D 미니게임입니다.

- Mathf.PerlinNoise에 라운드마다 달라지는 seed 값을 더해 장애물이 자연스럽게 흔들리도록 설계했습니다.
- 단순 Random 이동이 아니라 PerlinNoise를 사용해 움직임이 급격하게 튀지 않고 부드럽게 이어지도록 설계했습니다.
- Mathf.Lerp로 노이즈 값을 실제 이동 범위로 변환하고, Mathf.Clamp로 x축 이동 범위를 제한해 바늘이 플레이 불가능한 위치까지 이동하지 않도록 설계했습니다.
- 성공 / 실패 판정은 OnTriggerEnter2D에서 CompareTag를 사용해 바늘 부분과 통과 부분을 분리했습니다.

---

### 운석 피하기 게임

화면 상단에서 랜덤하게 생성되는 운석을 피해 제한 시간 동안 버티는 2D 회피형 미니게임입니다.

- Random.Range를 사용해 화면 상단의 x축 생성 위치를 매번 다르게 설정하고, Instantiate로 운석 프리팹을 생성했습니다.
- 생성된 운석의 Rigidbody2D velocity를 아래 방향으로 설정해 낙하하도록 구현했습니다.

## 트러블슈팅

### 1. 장애물 Collider 범위 오판정 문제

**PROBLEM**
실 통과 게임에서 화면상 실이 바늘에 닿지 않았음에도 실패 판정이 나오는 문제가 있었습니다.
Collider 범위가 실제 스프라이트보다 넓게 잡혀 있었고, 플레이어가 결과를 납득하기 어려운 실패 판정이 발생해 플레이 경험에 직접적인 영향을 주었습니다.

**APPROACH**
Collider 크기를 실제 스프라이트 영역에 맞게 재조정하고, 판정 기준을 시각적으로 보이는 장애물 범위와 일치시켰습니다.
OnTriggerEnter2D에서 CompareTag를 사용해 실패 조건과 성공 조건을 명확히 분리했습니다.
하나의 충돌 이벤트 안에서도 어떤 대상과 충돌했는지에 따라 결과가 다르게 처리되도록 구현했습니다.

**RESULT**
화면상 명확히 닿은 경우에만 판정이 발생해 플레이어가 결과를 예측하고 납득할 수 있는 판정 기준을 확보했습니다.
충돌 대상별 처리가 Tag 기준으로 분리되면서 성공 및 실패 로직도 더 명확하게 유지됐습니다.

### 2. Perlin Noise 고정 시드로 인한 패턴 반복 문제

**PROBLEM**
실 통과 게임의 장애물 흔들림을 Perlin Noise로 구현했는데, seed 값이 고정된 상수로 설정되어 있어 라운드를 재시작해도 장애물의 움직임 패턴이 매번 동일하게 반복됐습니다.
플레이어가 패턴을 학습하면 도전감이 사라지는 문제가 있었습니다.

**APPROACH**
라운드 시작 시 Random.value로 시드 값을 무작위로 생성해 PerlinNoise의 X 오프셋에 더하는 방식으로 수정했습니다.
PerlinNoise 자체는 부드러운 움직임을 유지하되, 매 라운드마다 다른 구간의 노이즈 값을 사용하도록 만들어 동일한 움직임이 반복되지 않도록 설계했습니다.

**RESULT**
라운드마다 다른 흔들림 패턴이 생성되어 반복 플레이에서도 장애물 움직임을 새롭게 판단하도록 개선했습니다.
미니게임의 단순 암기성을 줄이고, 짧은 시간 안에 반응해야 하는 회피 플레이의 도전감을 높였습니다.
